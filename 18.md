# Experiment 5: Library Database with Validation, Indexes and explain()

**Aim:** Create a Library database with 4 collections (`books`, `members`, `borrowRecords`, `authors`) with validation rules, insert at least 10 documents in each, create indexes (single-field, compound, text, unique), and show the performance difference using `explain()`.

## Where to run

1. Make sure MongoDB is running (if not, open CMD as Administrator and run `net start MongoDB`).
2. Open **Command Prompt** and type `mongosh`.
3. Paste each block below at the mongosh prompt, in order. Lines starting with `//` are comments and are safe to paste.

## a. Create the database and collections with validation

```javascript
use LibraryDB
```

**Books collection**

```javascript
db.createCollection("books", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["isbn", "title", "authorId", "publishedYear", "copiesAvailable"],
      properties: {
        isbn: { bsonType: "string", description: "must be a string and unique" },
        title: { bsonType: "string" },
```


## d. Performance test with explain()

**i. Without index**

```javascript
db.books.dropIndexes()
db.books.find({ isbn: "B007" }).explain("executionStats")
```

**ii. With index**

```javascript
db.books.createIndex({ isbn: 1 })
db.books.find({ isbn: "B007" }).explain("executionStats")
```

What to compare in the output:

| Field | Without index | With index |
|---|---|---|
| `winningPlan.stage` | `COLLSCAN` (reads every document) | `IXSCAN` (uses the index) |
| `executionStats.totalDocsExamined` | all documents in the collection | 1 |
| `executionStats.executionTimeMillis` | higher | lower |

## e. Additional indexed queries

**i. Find books by a specific author quickly**

```javascript
// Create index on author for fast lookup

// Query to find all books by "George Orwell"

```

**ii. Search books by title keyword (text index)**

```javascript
// Create text index on title
db.books.createIndex({ title: "text" })

// Search for books containing the word "Mockingbird"
db.books.find({ $text: { $search: "Mockingbird" } }).explain("executionStats")
```

**iii. Find overdue books efficiently**

```javascript
// Create index on dueDate for borrowings
db.borrowings.createIndex({ dueDate: 1 })

// Find books that are overdue (before today)
db.borrowings.find({ dueDate: { $lt: new Date() } }).explain("executionStats")
```

**iv. Get borrowing history of a specific member, sorted by date**

```javascript
// Create compound index for memberId and borrowDate
db.borrowings.createIndex({ memberId: 1, borrowDate: -1 })

// Find member's borrowing history
db.borrowings.find({ memberId: 105 }).sort({ borrowDate: -1 }).explain("executionStats")
```

# Experiment 6: Sharding in MongoDB

**Aim:** Show how sharding works by running a sharded cluster (3 shards, 1 config server, 1 mongos router) on one Windows PC.

## Window plan (8 windows in total)

| Window | What it is | Command | Keep open? |
|---|---|---|---|
| A | Admin CMD (setup and cleanup) | `net stop`, `mkdir` | Can close after Step 3 |
| 1 | Config server | `mongod --configsvr ...` | **Yes** |
| 2 | mongosh on port 27021 | `mongosh --port 27021` | Close after Step 4 |
| 3 | Shard 1 server | `mongod --shardsvr ...27018` | **Yes** |
| 4 | Shard 2 server | `mongod --shardsvr ...27019` | **Yes** |
| 5 | Shard 3 server | `mongod --shardsvr ...27020` | **Yes** |
| 6 | mongosh to initialize shards | `mongosh --port 27018/27019/27020` | Close after Step 6 |
| 7 | mongos router | `mongos --configdb ...` | **Yes** |
| 8 | mongosh connected to mongos | `mongosh --port 27017` | **Yes** (all final work here) |

**Ports:** config server 27021, shard1 27018, shard2 27019, shard3 27020, mongos 27017.

## Step 1: Verify installation (Window A)

Open **Command Prompt**. Type:

```cmd
mongod --version
mongosh --version
mongos --version
```

Each should print a version number. If you see `'mongod' is not recognized`, add MongoDB's `bin` folder (for example `C:\Program Files\MongoDB\Server\<version>\bin`) to the Windows **PATH**, then open a **new** CMD window and try again.

## Step 2: Free the ports (Window A, must be Administrator)

Search **cmd** in the Start menu, right-click, **Run as administrator**. Type:

```cmd
net stop MongoDB
taskkill /IM mongod.exe /F
taskkill /IM mongos.exe /F
netstat -ano | findstr :270
```

- The Windows MongoDB service normally uses port 27017, which is the port mongos needs. That is why `net stop MongoDB` is important.
- Errors such as "service is not started" or "process not found" are fine.
- If `netstat` still shows something listening on 27017 to 27021, note its PID (last column) and run `taskkill /PID <pid> /F`.

## Step 3: Create data folders (Window A)


Lots of log text will scroll. **Leave this window open.** If Windows Firewall asks for permission, click **Allow**.

## Optional: Sharded vs unsharded performance comparison (matches the Aim)

Run in **Window 8**.

### A. Load 100,000 records into the sharded collection

```javascript
use UniversityDB
let docs = [];
for (let i = 1; i <= 100000; i++) {
  docs.push({ student_id: 1000 + i, name: "Student" + i, department: ["CSE","ECE","ISE"][i % 3] });
  if (docs.length === 10000) { db.Students.insertMany(docs); docs = []; }
}
db.Students.getShardDistribution()
```

Now the three shards should each hold roughly one third of the data. The total will show about **100009** documents (your 9 original records plus the 100,000 new ones).

### B. Create an unsharded copy with the same data

```javascript
db.createCollection("Students_Unsharded")
let docs2 = [];
for (let i = 1; i <= 100000; i++) {
  docs2.push({ student_id: 1000 + i, name: "Student" + i, department: ["CSE","ECE","ISE"][i % 3] });
  if (docs2.length === 10000) { db.Students_Unsharded.insertMany(docs2); docs2 = []; }
}
```

### C. Compare the two with explain

```javascript
db.Students_Unsharded.find({ student_id: 55000 }).explain("executionStats")
db.Students.find({ student_id: 55000 }).explain("executionStats")
```

Note these values from each output and write them in your record:

| What to look at | Unsharded (no index) | Sharded |
|---|---|---|
| `executionStats.executionTimeMillis` | (your value, for example 37) | (your value, for example 0 or 1) |
| `executionStats.totalDocsExamined` | 100000 (full scan) | 1 (uses the index on one shard) |
| `queryPlanner.winningPlan.stage` (top level) | `SINGLE_SHARD` | `SINGLE_SHARD` |
| `queryPlanner.winningPlan.shards[0].winningPlan` (inside) | `COLLSCAN` | `FETCH` then `IXSCAN` |

> Because you are connected through mongos, **both** queries show `SINGLE_SHARD` at the top level. The real difference is one level deeper: the unsharded query scans every document (`COLLSCAN`), while the sharded query uses the hashed index (`IXSCAN`) and examines only 1 document. Exact milliseconds will differ on your PC.

For an honest comparison, you can also add a normal index to the unsharded copy and re-run:

```javascript
db.Students_Unsharded.createIndex({ student_id: 1 })
db.Students_Unsharded.find({ student_id: 55000 }).explain("executionStats")
```

A query that does **not** use the shard key must ask every shard. The top-level stage becomes `SHARD_MERGE` and all 3 shards appear in `winningPlan.shards`:

```javascript
db.Students.find({ department: "CSE" }).explain("executionStats")
```

> Since all shards run on one PC here, the main thing you demonstrate is **how queries are routed** (targeted vs all shards). Real speed gains come when shards are on separate machines.

## How data flows

1. Client sends a request to **mongos**.
2. mongos reads shard placement from the **config server**.
3. Using the **shard key**, mongos picks the shard(s).
4. The shard(s) process the request.
5. The result returns through mongos to the client.

## Stop the environment

Click each window running `mongod` or `mongos` (Windows 1, 3, 4, 5, 7) and press **Ctrl+C**. Then type `exit` in Window 8. Do **not** delete `C:\MongoSharding` if you want to keep your data.

## Starting it again later

The one-time steps (`rs.initiate`, `sh.addShard`, `sh.enableSharding`, `sh.shardCollection`) are already saved. Next time, only start the processes in this order, each in its own window:

1. Config server (Step 4.1)
2. Three shards (Step 5)
3. mongos (Step 7)
4. `mongosh --port 27017` for your work

## Troubleshooting

| Problem | Reason | Fix |
|---|---|---|
| `'mongod' is not recognized` | `bin` folder not in PATH | Add to PATH, open a new CMD |
| `Address already in use` | Port taken (often the Windows service on 27017) | Do Step 2 again |
| `NotYetInitialized` | `rs.initiate()` not run | Connect to that port and run `rs.initiate(...)` |
| `No primary detected` | Replica set still electing | Wait, check `rs.status()` |
| `addShard` fails | Shard not running or wrong replica set name | Check the shard window is open and the name matches (`shard1RS` etc.) |
| `Connection refused` | Process not running on that port | Start it and verify the port |
| Prompt is not `mongos` | Connected to wrong port | `exit`, then `mongosh --port 27017` |

## Program

```python
import tkinter as tk
from tkinter import messagebox
from pymongo import MongoClient

# MongoDB connection
client = MongoClient("mongodb://localhost:27017/")
db = client["collegeDB"]
collection = db["students"]

# Insert student record into MongoDB
def insert_student():
    name = name_entry.get()
    roll = roll_entry.get()
    branch = branch_entry.get()
    cgpa = cgpa_entry.get()

    if not (name and roll and branch and cgpa):
        messagebox.showwarning("Input Error", "All fields are required!")
        return

    try:
        cgpa = float(cgpa)
        collection.insert_one({"name": name, "roll": roll, "branch": branch, "cgpa": cgpa})
        messagebox.showinfo("Success", "Student record inserted.")
        name_entry.delete(0, tk.END)
        roll_entry.delete(0, tk.END)
        branch_entry.delete(0, tk.END)
        cgpa_entry.delete(0, tk.END)
    except ValueError:
        messagebox.showerror("Invalid Input", "CGPA must be a number.")

# Display all student records
def display_students():
    students = collection.find()
    result_text.delete("1.0", tk.END)
    for s in students:
        result_text.insert(tk.END, f"{s['name']} | {s['roll']} | {s['branch']} | {s['cgpa']}\n")

# GUI setup
app = tk.Tk()
app.title("Student Database App (MongoDB)")

tk.Label(app, text="Name:").grid(row=0, column=0)
name_entry = tk.Entry(app)
name_entry.grid(row=0, column=1)

tk.Label(app, text="Roll No:").grid(row=1, column=0)
roll_entry = tk.Entry(app)
roll_entry.grid(row=1, column=1)

tk.Label(app, text="Branch:").grid(row=2, column=0)
branch_entry = tk.Entry(app)
branch_entry.grid(row=2, column=1)

tk.Label(app, text="CGPA:").grid(row=3, column=0)
cgpa_entry = tk.Entry(app)
cgpa_entry.grid(row=3, column=1)

tk.Button(app, text="Insert Student", command=insert_student).grid(row=4, column=0, columnspan=2, pady=10)
tk.Button(app, text="Show All Students", command=display_students).grid(row=5, column=0, columnspan=2, pady=5)

result_text = tk.Text(app, width=50, height=10)
result_text.grid(row=6, column=0, columnspan=2, padx=10, pady=10)

app.mainloop()
```

### What the code does (for viva)

- `MongoClient("mongodb://localhost:27017/")` connects Python to the MongoDB server.
- `client["collegeDB"]` selects the database; `db["students"]` selects the collection. MongoDB creates both automatically on the first insert.
- `insert_student()` reads the four text boxes, checks none is empty, converts CGPA to a number, and saves one document with `insert_one`.
- `display_students()` reads all documents with `find()` and prints each one in the text box.
- The `tk` lines build the window: labels, text boxes, two buttons and a result area.
- `app.mainloop()` keeps the window open and waiting for clicks.

## Troubleshooting

| Problem | Fix |
|---|---|
| `python` is not recognized | Use `py` instead, or reinstall Python with "Add to PATH" ticked |
| `No module named pymongo` | Run `python -m pip install pymongo` again |
| `ServerSelectionTimeoutError` or a long hang on Insert | MongoDB is not running. Start it (`net start MongoDB` as Admin, or `mongod --dbpath C:\data\db`) |
| `can't open file 'student_app.py'` | You are in the wrong folder (use `cd Desktop`) or the file was saved as `.py.txt` |
| Popup: "CGPA must be a number" | Enter digits only, for example `8.5` |
| Window 1 shows nothing | Run `use collegeDB` first, then `db.students.find()` |
| Want to clear test data | In mongosh: `db.students.deleteMany({})` |
